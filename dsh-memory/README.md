# dsh-memory

**中文** · 跨会话记忆插件：让 DSH 的 agent 记住犯过的错、做成功的路子和验证过的规则，并在会话结束后自动 **dreaming**——对照会话记录纠错、合并、精简记忆。不修改 DSH 源码，卸载即恢复内置行为（记忆文件保留在原处）。

思路来自 Anthropic Engineering《The components of agent memory》：当下用会话记录忠实留痕，用克制的笔记捕捉环境给不了的判断，事后再以原始记录为依据离线整理。

## 它做什么

| 部分 | 行为 |
| --- | --- |
| 记忆笔记 | agent 用 `memory_list` / `memory_read` / `memory_write` / `memory_delete` / `memory_move`（改名或在分区间移动，一步完成）/ `memory_search`（在分区内搜文字）读写记忆；分**项目级**（当前工作目录，默认）和**用户级**（跨项目）两个分区 |
| 分区准入 | 工具要求声明：新建用户级笔记必须带 `basis: "user-stated"`（用户亲口说的偏好或工作方式）。这个声明由模型自己给出，工具只检查有没有，不核实真假，因此它是对模型的约束而不是安全边界；看似通用的教训先写进项目区并标 `candidate: user`，等跨项目整理确认至少两个项目都成立后再提升 |
| 大小限制 | 由工具强制：`INDEX.md`（文件名不分大小写）超过上限（默认 4 KB）或单行超过 240 字节时拒绝写入；笔记路径里的 `:`、`*`、`?`、结尾的点或空格、`CON` 这类设备名也会被拒绝；单篇笔记超过 3 KB 时照写，但提示拆分 |
| 索引注入 | 每个会话开始时注入两个分区的 `INDEX.md`，正文按需读取；会话内的改动下个会话生效 |
| dreaming | 会话最后一轮结束后空闲 10 分钟，或会话关闭时，在后台起一个隐藏的整理 agent：只给它记忆工具和本项目的会话记录，按"纠错 → 合并 → 索引瘦身 → 修悬空链接 → 补漏记的教训"的顺序整理，最后提交一份整理报告。悬空链接、没挂进索引的笔记、超限的 INDEX 和笔记由代码事先算好放进提示词，不让模型花步数去找 |
| 跨项目整理 | 唯一能同时看到所有分区的整理：把只属于某个项目的用户级笔记移回该项目，把两个以上项目都成立的教训提升到用户区，去重、拆分混杂的笔记。有项目整理过后每天自动跑一次，设置页「立即 dream」最后也会跑一次 |
| 设置页 | 设置侧栏「记忆」：总开关、自动 dreaming、空闲阈值、并发数、索引大小上限、dreaming 模型与思考强度、最近运行日志（点「详情」看摘要、改动了哪些笔记、遗留的问题和改动前的备份位置）、待处理数、「立即 dream」 |
| `/dream` | 立即整理当前项目的记忆，完成后返回摘要 |

记忆存放在 `<DSH home>/memory/`（默认 `~/.dsh/memory/`）：

```
memory/
  user/                 跨项目：偏好、通用教训
  projects/<项目>/      本项目的规则、陷阱、做法
  .state/               插件状态：dreaming 队列与日志，以及 history/（每次整理前被改动笔记的原文件）
```

都是普通 Markdown，可以直接查看、编辑或删除。

## 安装

```powershell
# 从 GitHub
dsh plugin --profile web add -w "github:JiaMingWang-CN/dsh-bundles#path:dsh-memory"

# 本地目录
dsh plugin --profile web add -w C:\path\to\dsh-bundles\dsh-memory
```

## 费用与失败

- dreaming 会调用模型、消耗你自己的 token。默认用 DSH 的默认模型，可在设置页选另一个模型并调整思考强度（强度越高越仔细，也越费 token）；不想自动运行就关掉「自动 dreaming」，改用 `/dream` 手动触发。
- **隐私**：整理时模型读到的是你的会话记录。选了别的 provider 的模型，所有项目的会话内容（含其中出现的代码、路径和粘贴的文本）都会发给那个 provider。整理 agent 被要求把会话记录和笔记当数据而非指令，也不得把密钥、令牌、口令等写进笔记，但这些主要是提示词里的约束；代码只拦截几种一眼可认的密钥（私钥块、AWS/GitHub/OpenAI 式 key、Slack 令牌、Google API key），其余没有拦截，请不要在会话里粘贴你不愿被记住的机密。
- 只有值得整理的会话才排队：至少两轮正常完成的对话，或一轮正常完成且调用过工具（记忆工具不算）。问候、被中止的会话不会触发；它们的活动会累计，等会话真正做了事再一起整理。
- 每次整理有步数上限（单个项目 40 步，跨项目 80 步）。到上限就停下，已做的改动保留，日志里记一条问题。没读到结尾的会话不会出队：水位线只推进到 agent **最后一次改笔记时**已连续读到的位置（光读不写不算整理，跳着读跳过的部分也不算已读），下一次整理从那里接着读（提示词里会写 `session-x (from seq N)`）；连续三次没有任何进展的会话会被放弃并记入日志。为了不让 agent 把步数全花在阅读上，一次项目整理最多读 20 页转录，超出后 `transcript_read` 会提示先写笔记再收尾。已读完的会话不受影响。
- 长会话每次空闲后重新排队时，只整理水位线之后的新内容，不会从头重读。转录读取按事件分页，单行最多 2000 字符，用户粘贴的大段日志不会撑爆整理 agent 的上下文。
- 不同项目的 dreaming 并行执行，最多同时跑「并发数」个（默认 4，设置页可改，设为 1 即全局串行）；同一项目始终一次只跑一个。并行的运行同时改同一篇用户级笔记时，后写的一方会遇到版本冲突，重新读取后在新内容上重做，不会覆盖对方。
- 日志区分三种结果：✔ 成功；⚠ 完成但有遗留问题（工具报错、整理 agent 报告没能核对或修好的内容、没提交报告、到了步数上限），批次照常出队；✖ 失败。改动按笔记计数：同一篇写几次只算一次。
- 失败按原因分开处理。**鉴权或额度类**（401/403、key 无效、额度不足）立即**暂停自动 dreaming**；**瞬时类**（429、5xx、超时、网络中断）不暂停，等 1 分钟、再等 3 分钟后自动重试，连续三波失败才暂停（并行的几个项目同时失败算一波）；**手动运行**失败一律暂停。暂停时设置页显示原因和该怎么办，暂停期间结束的会话只排队、不调用模型。排查后点「立即 dream」或运行 `/dream`，成功后按结束顺序补完队列并恢复自动。
- 某个批次稳定地触发同一类失败（模型拒答 `blocked`、输出被截断 `max-tokens` 等）时，按会话计数；失败两次后该会话单独运行，第三次失败才把它放弃并记入日志，同批的其他会话不受牵连，也不会为此暂停。
- 项目目录暂时不可达（移动硬盘或网络盘没挂载）时，这次整理被跳过：会话继续排队，10 分钟后再看，既不记失败也不暂停；只有它所在的上级目录确实存在而项目目录没了，才按“项目已删除”处理（项目区只读，仅保留用户亲口说的偏好）。
- 关闭总开关或卸载插件时，正在跑的整理会被取消，不会继续消耗 token 或写记忆；它们的批次留在队列里。
- 一次错误之后的自动恢复不依赖你：状态文件损坏时会改名为 `state.json.corrupt-*` 并从空队列重新开始，不会让插件加载失败。
- 退出应用时正在排队或运行的会话会留在队列里，不会触发暂停。下次启动约 30 秒后会补登漏掉的结束事件，并**立即开始处理积压的队列**（自动 dreaming 开着时）；在设置页打开总开关、打开自动 dreaming 或调大并发数，也会立刻开始处理已排队的会话。不想启动时消耗 token，就关掉「自动 dreaming」。
- 跨项目整理不会在第一次项目整理后立刻触发，而是从那时起算一天；自动触发时，若有笔记的项目少于 2 个且用户区没有笔记，就跳过（手动触发照常运行）。
- 整理会改动、删除笔记，改动前的原文件按运行保存在 `memory/.state/history/<整理会话 id>/`（保持原目录结构，保留最近 20 次），要撤销就把文件复制回去。设置页日志「详情」里能看到这次运行的摘要、改动的笔记和备份位置。

## 已知限制

- 只适配 DSH **0.2.2-rc.1**：依赖的会话、agent、提示词接口仍是 rc 版本，升级 DSH 后需要重新验证。
- 子代理会话（有工作目录的）也会注入两份记忆索引，但换成一小段只读指引，并且 `memory_write` / `memory_delete` / `memory_move` 对它们直接拒绝：子代理的会话不进入整理队列，没人复核它写的笔记，也判断不了分区准入。值得记的东西由它在结果里告诉父代理，由父代理决定。
- 笔记目录下的空文件夹会在删除笔记时顺手清掉，崩溃遗留的临时文件启动时清理；已删除项目的分区目录不会自动删除（里面可能有你想保留的内容），可自行删除 `memory/projects/` 下对应目录。
- 提示和界面文案是中文，没有多语言切换。
- dreaming 使用的隐藏会话保存在 `~/.dsh/sessions/_no-cwd/`，标题固定为「记忆整理 · 项目名」，不会出现在会话列表和搜索里。插件按磁盘上的会话内容识别自己的整理会话，只保留最近 50 个；重装插件、状态重置后留下的旧会话也会被清理，其他隐藏会话不受影响。
- 启动时只为最近 7 天内**创建**的会话补登漏掉的结束事件；更早创建、仍在使用的会话，若宿主崩溃时有未整理的内容，要等它下次结束或运行 `/dream` 才会处理。

## 开发

```powershell
cd dsh-memory
pnpm install
pnpm test
```

建议 Node.js 22.15 或更新（`zlib` 才有 zstd）；更低版本能加载，只是跳过对 zstd 压缩的整理会话的清理。仓库里的 GitHub Actions 会在每次推送时跑这套测试。
